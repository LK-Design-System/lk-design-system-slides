# 제안 — 열람 덱 kind 축 (콘텐츠 규율·구도·계약의 이원화)

상태: **구현됨** (2026-08-17 작성, 같은 날 변경 1~5 전부 구현. 완료 정의
충족: 파일럿 덱이 자기 핀 0개로 전 게이트를 통과하고 손 구현이 TopicList·
ExhibitRow·WeekSpanRows 호출로 대체됐다. 남은 것은 열린 질문의 body-cap
재측정뿐)
근거: [READING_DECK_PILOT.md](./READING_DECK_PILOT.md) — 실제 LKR 주간
업무현황 4장을 한 장 밀도로 옮기며 확보한 마찰 6건과 계약 후보 3종.

문제를 한 문장으로: **현행 시스템의 축은 시청 거리(preset: keynote/briefing)
뿐이라, 소비 방식이 다른 덱 — 발표되지 않고 회람·열람되는 덱 — 이 발표 덱의
콘텐츠 문법(주장 문장 강제, 본문 140자, 캔버스 균형 구도)을 강제당한다.**
파일럿이 실측한 결과, 이 문법과 열람 장르의 충돌은 스타일이 아니라 규율의
문제였다: 지어낸 거버닝 3개, 산출물로 샌 실험 메타데이터 1건, 잘못 적용된
가운데 구도 2건이 전부 "시스템이 자리를 주니 채운" 텍스트·구도였다.

## 장르 정의 (제안의 대상)

**열람 덱**(leave-behind / Duarte의 slidedocs): 메신저로 회람되고 책상에서
스캔된다. 발표자 서사가 없으므로 페이지 단위로 완결되고, "한 페이지 한
주제"(경과+수치+증거)가 미덕이다. 주간 업무현황이 전형. 발표 덱과 화면
지오메트리·토큰 체계는 **공유한다** — 파일럿에서 briefing 토큰 프로파일,
editorial seam, 하단 크롬, fit 사다리가 전부 공짜로 작동했다. 다른 것은
콘텐츠 규율과 구도 규칙이다.

## 설계 제약 — 이 제안이 지켜야 하는 것

- kind는 **콘텐츠 규율 축**이지 토큰 축이 아니다. preset(keynote/briefing)과
  직교한다 — 열람 덱은 보통 briefing이지만 kind가 preset을 함의하지 않는다.
- 새 토큰 체계를 만들지 않는다. 파일럿의 결론: 열람 모드의 본체는 **게이트
  프로파일 + 콘텐츠 컴포넌트 계약 3종**이다.
- 게이트의 라쳇 성질(known-failures는 줄기만 한다)을 유지한다. kind 도입은
  핀을 늘리는 게 아니라 **파일럿의 핀 2개(body-cap, governing-required)를
  합법화해 제거**하는 방향이다.

## 변경 1 — 덱 kind 축과 게이트 프로파일

`DeckViewer`에 `kind` prop을 신설한다 (`'present'` 기본 | `'read'`).
역할은 둘: ① 덱 루트에 `data-lds-deck-kind`를 찍어 게이트가 읽게 한다,
② 문서·스킬이 참조할 공식 어휘가 된다.

```jsx
<DeckViewer label="8월 2주차 LKR 업무현황" kind="read">
```

`check:deck-content`는 kind별 프로파일로 감사한다:

| 규칙 | present (현행 유지) | read | 근거 |
|------|--------------------|------|------|
| title-noun-final | 유지 | **유지** | 명사형 종결은 장표 공통 관용구 |
| governing-required | 유지 | **해제** | 마찰 4 — 열람 관용구는 명사형 제목+전시물로 완결, 메시지 라인 없음. 요약이 필요하면 회람 메시지(메신저 본문)가 밖에서 한다 |
| governing-shape | 유지 | 유지 (썼다면 형태는 지킨다) | 선택이 되는 것이지 문장 규격이 풀리는 게 아니다 |
| body-cap | 140자 | **300자** | 마찰 1 — 실측 251자 + present와 같은 비율의 여유(140/120≈1.17, 251×1.17≈294→300) |
| bullet-count | 7 | 유지 | 파일럿 최다 리스트 항목 5 — 상한 완화 근거 없음 |
| statement-budget | 유지 | 유지 | 열람 덱에 Statement가 온다면 같은 예산 |
| source-required | 유지 | 유지 | 빌린 데이터의 출처는 장르 무관 |
| img-alt / img-unsized | 유지 | 유지 | 마찰 2 — 리플로·접근성은 장르 무관 |
| end-residue | 유지 | 유지 | 열람 덱은 보통 막지가 없다 — 있다면 같은 규칙 |
| canvas-under-fill | 유지 | **해제** | 마찰 6 — 상단 쏠림은 문서 흐름이지 결함이 아니다 |

프로파일은 게이트 스크립트 안의 표 하나로 둔다(규칙 함수는 공유, 임계값과
적용 여부만 kind가 가른다). 감사 시 kind는 덱 루트의 data 속성에서 읽는다 —
스토리 메타가 아니라 **렌더된 실물**이 출처다.

핀 정리: 파일럿 덱이 `kind="read"`를 달면 body-cap·governing-required가
울리지 않게 되고, (덱, 규칙) 단위 라쳇이 "핀이 실제보다 넓다"고 실패한다.
그때 핀 2개를 제거한다 — 라쳇이 제안 구현의 완료 증명이 된다.

## 변경 2 — 콘텐츠 컴포넌트 계약 3종 승격

파일럿이 손으로 정의한 것을 컴포넌트로 승격한다. 셋 다 editorial 가족이다
(`--editorial-*` seam과 표 문법을 재사용하고, 매체가 밀도를 재지정한다).
초안 값은 파일럿 확정 값 그대로:

**2-1. `TopicList` — 2단계 리스트.** 대항목 body·semibold·strong / 세부
caption·regular·neutral / 들여쓰기 `--editorial-cell-pad-inline` / 항목 간
`--space-5`, 세부 간 `--space-2`. 원본 PPT의 3단 들여쓰기에서 실제 필요한
위계는 2단뿐이었다(파일럿 1·2호에서 페이지 유형을 건너 재사용 검증).

```jsx
<TopicList items={[{ topic: '대덕특구', details: ['시뮬레이션 기반 검증 완료', /* … */] }]} />
```

**2-2. `ExhibitRow` — 복수 전시물 행.** N열 grid + `--editorial-figure-gap`
+ **잔여 높이 주도** 이미지(`minmax(0,1fr)` + `height:100%`, ImageSlide의
height-driven 계약과 동일) + ellipsis 한 줄 캡션(fine 스케일). 발표 덱의
"한 장 한 전시물"과 달리 열람 페이지는 증거를 본문 곁에 둔다. 고정 높이
전시물은 크롬 스필의 원인이었으므로(마찰 3) 계약에서 배제한다.

```jsx
<ExhibitRow exhibits={[{ src, caption: '시뮬레이션 화면 — P0002 추적 중' }]} />
```

**2-3. `WeekSpanRows` — 주차 스팬 행 (간트-lite).** 표의 밴딩 문법 + 밀도
seam 위에: ① **시간 격자** — 주차 칸 왼쪽 헤어라인(`line-normal-neutral`)
눈금, 헤더는 칸 중앙(눈금 없는 바는 축 위 스팬이 아니라 떠 있는 선으로
읽힌다), ② 스팬 바는 칸별 조각이 아니라 **grid-column 한 몸**(무단절 규칙의
구현, 이음매 제거), ③ 기간 너머 계속은 바와 같은 토큰의 화살촉이 표 끝을
살짝 넘는다 — 원본 관용구의 번역. 비율은 블록 화살표 고전(샤프트 10px,
촉 20px — 촉이 샤프트의 2배로 벌어져야 화살표로 읽힌다).

```jsx
<WeekSpanRows weeks={['8월 2주차', '8월 3주차']}
  rows={[{ name: '화재 검출', work: '화재 데이터셋 수집 및 학습', from: 0, to: 1, continues: true }]} />
```

승격 절차 주의: 스토리 3건 추가는 **레지스터 3종 동기화 세트**다
(dedup 계약 해시, IA 감사 리뷰 마킹, 인벤토리 문서). 파일럿 덱은 승격 후
손 구현을 컴포넌트 호출로 교체한다 — 위성 중복 은퇴의 미니어처.

## 변경 3 — 크롬 존 침범 가드

마찰 3의 게이트 사각: 콘텐츠가 캔버스 패딩 존(출처·푸터 밴드)으로 흘러도
surface `scrollHeight`는 자라지 않아 `check:slide-overflow`가 못 잡는다.
가드를 추가한다 — 콘텐츠 영역의 painted 최하단이 크롬 밴드(푸터·출처 존의
상단)을 넘으면 위반. 측정은 canvas-under-fill과 같은 painted 기준(텍스트
레인지 + replaced 요소)을 재사용하고, 같은 walk 안에서 잰다. 이 가드는
**kind 무관**이다 — 7차 대장의 "briefing 출처 존 11px 침범"과 같은 뿌리로,
발표 덱도 보호한다.

## 변경 4 — "스팬·레일 무단절" 규칙 명문화

세 번 반복된 규칙을 계약 문구로 승격한다: **연속을 뜻하는 도형(타임라인
레일, 간트 스팬 바, 진행 트랙)은 칸·노드 경계에서 끊기지 않는다. 끊긴
스팬은 두 개의 일정으로 읽힌다.** 실행 수단:

- 문구: 스킬 레퍼런스 `components.md`의 해당 컴포넌트 항목과 컴포넌트 소스
  주석에 명시.
- 단언: `WeekSpanRows`는 행당 스팬 바가 **한 요소**임을 play로 단언
  (`[data-span-bar]` 카운트 = 행 수). NarrativeTimeline 가로 레일의 기존
  단언과 같은 계열.

## 변경 5 — 콘텐츠 규율 문서와 스킬의 kind 분기

- `content-rules.md`에 **열람 프로파일** 섹션: 변경 1의 표 + 두 규율:
  ① **빈 슬롯은 비워둔다** — 파일럿의 어긋난 텍스트 3건(거버닝 2회, 표지
  부제)은 전부 "시스템이 자리를 주니 지어 채운" 문장이었다. 열람 덱에서
  요약·주장 문장이 필요하면 회람 메시지가 밖에서 한다. ② **표지 관용구** —
  제목·소속·보고자·주차로 완결, 내용 요약 부제 금지. 실험·제작 메타데이터는
  notes와 문서의 몫이지 캔버스의 몫이 아니다.
- `lds-deck` 스킬: 1단계(입력 판별)에 **kind 판별**을 추가한다 — "발표하러
  가는 덱인가, 읽으라고 보내는 덱인가." 4단계 구도 지침 중 `anchor="center"`
  ·희소 채움 규칙은 **present 전용**으로 스코프를 명시한다(마찰 6 — 열람
  페이지는 문서처럼 위에서 아래로, 본문이 제목에 붙는다). 고스트 덱 테스트는
  read에서 "거버닝 체인" 대신 "제목 체인"으로 대체한다 — 명사형 제목만 이어
  읽어 보고의 목차가 서는지.

## 이 제안에 없는 것

- **라쳇 규칙 단위 입도** (마찰 5): 이미 해소됨 — `check:deck-content` 핀이
  (덱, 규칙) 쌍 단위로 좁혀졌다. 변경 1의 핀 정리가 이 입도에 의존한다.
- **kind의 슬라이드 단위 오버라이드** (발표 덱 속 부록 열람 페이지 등):
  실물 증거가 없다. 덱 단위로 시작하고, 혼합 덱이 실제로 나타나면 그때
  슬라이드 오버라이드를 논의한다 — 파일럿이 이 제안에 했던 것과 같은 절차로.
- **PPTX/PDF 내보내기**: 열람 덱이 가장 필요로 할 배포 경로지만 별개 작업이다
  (README 다음 단계 항목 유지).

## 구현 순서와 검증

1. **kind 축** (변경 1): DeckViewer prop + 게이트 프로파일 → 파일럿 덱에
   `kind="read"` → 라쳇이 핀 2개의 과잉을 알리면 제거 → 전 게이트 그린.
2. **크롬 가드** (변경 3): 가드 추가 → 전 덱 재감사 → 기존 위반은 (덱, 규칙)
   핀으로 명시하고 사유 기록.
   - 구현 기록 (2026-08-17): 가드가 즉시 실물 2건을 드러냈다. ① `매체와
     논증의 분리` 12/14장 "배포 전 관문" — 크롬 밴드 54px 침범 (가드가
     없던 시절 통과했던 기존 결함, 수정 대상). ② `스트리밍 이관 제안` —
     painted 측정에서 출처 라인이 콘텐츠로 세지던 것을 바로잡자
     canvas-under-fill 3장이 정직하게 드러남 (47·44·43%). 둘 다 (덱, 규칙)
     핀으로 명시 — 콘텐츠 수선은 이 제안 범위 밖의 후속.
   - 후속 해소 (2026-08-17): 두 결함 모두 콘텐츠 수선으로 닫혔다. ① "배포 전
     관문"을 정적·실행 두 장으로 쪼갰다(스타일 축소가 아니라 분할 — 거버닝
     체인이 한 마디 늘어 10개). ② 스트리밍 3장은 `anchor="center"`로 잔여
     높이의 세로 중앙에 놓았다. 라쳇이 핀 2개의 과잉을 알렸고, 제거해
     **핀 0**이 됐다.
3. **계약 승격** (변경 2): 컴포넌트 3종 + 스토리 + play 단언(무단절 포함,
   변경 4) + 레지스터 3종 동기화 → 파일럿 덱을 컴포넌트 호출로 교체 →
   렌더 눈 검수(간트 격자·바 이음매·전시물 높이).
4. **문서·스킬** (변경 5): content-rules 열람 프로파일 + lds-deck kind 분기.

각 단계 끝마다 `npm run check:storybook` 전체와 파일럿 4장 실물 캡처 리뷰.
완료 정의: 파일럿 덱이 **핀 0개**로 전 게이트를 통과하고, 손 구현이 컴포넌트
호출로 대체된 상태.
