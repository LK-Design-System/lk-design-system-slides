# 내용 규율

컴포넌트가 강제하지 못하는 것 — 무엇을 말할지, 어떤 순서로 말할지 — 을 여기서 잡는다.
(액션 타이틀·고스트 덱·전시물 규율은 academic-pptx-skill에서, 워크플로 골격은
make-slide에서 가져와 이 시스템의 계약에 맞게 번안했다. 둘 다 MIT.)

이 문서의 규칙 중 **숫자가 있는 것은 `check:deck-content`가 기계로 집행한다**
(명사형 종결·거버닝 유무와 형태·불릿 수·본문 상한·source·StatementSlide 예산·막지 잔향 —
각 임계값의 출처는 그 스크립트 머리 주석에 있다). 숫자가 없는 것 — 고스트 덱, 레이아웃
적합, 다양성, 마감 — 은 `qa/rubric.md`의 심사 차원이다. 게이트는 바닥이지 검증이 아니다.

## 1. 논증 구조

**덱 하나에 논증 하나.** 자료 전체를 발표하려 하지 말 것. 주어진 시간 안에 설득
가능한 주장 하나를 고르고, 나머지는 부록 챕터로 보낸다.

**서사 축을 하나 골라 일관되게:**
- **상황 → 문제 → 해결** (기본): 알려진 것 → 부족한/깨진 것 → 이 제안의 기여
- **결론 우선**: 시간 압박이 큰 경영 보고. 결론을 먼저, 근거를 뒤에.

**연구 질문/핵심 주장은 3장 안에 등장**시킨다. 뒤로 미루면 청중이 근거를 평가할
기준이 없다. 덱이 도는 결정적 주장 하나는 `StatementSlide`로 독립시킬 수 있다 —
단, 덱에 한두 번이 한계다. 남발하면 무게가 죽는다.

**슬라이드 하나에 일 하나.** 한 슬라이드가 두 가지를 하고 있으면 쪼갠다.

**서사 축은 청중으로 고른다** (원전 academic-pptx-skill의 매핑, 번안에서 떨어뜨렸던 것):
상황→문제→해결은 끝까지 앉아 있는 청중(세미나·기술 공유)의 축이고, 결론 우선은
끝까지 안 앉아 있을 수 있는 청중(경영 보고·심사·짧은 브리핑)의 축이다. 축을 고르고
나면 중간에 바꾸지 않는다.

## 2. 제목과 거버닝 — 역할 분담

이 시스템에서는 academic의 "액션 타이틀"이 두 자리로 나뉜다:

| 자리 | 소유 | 형식 | 예 |
|------|------|------|-----|
| `title` | 명사형 종결 라벨 | "~다" 금지 | "복구 시간 절반 단축" |
| `governing` | 완결 문장 한 개의 주장 | 본문이 입증할 문장 | "평균 복구 시간이 작년 동기 대비 절반으로 줄었다." |

- **고스트 덱 테스트는 거버닝 체인으로** 한다: 거버닝만 이어 읽어 논증이 성립하는가.
- 거버닝이 없는 콘텐츠 슬라이드는 "주장이 없는 슬라이드"다 — 목차·간지·표지가 아닌데
  거버닝을 못 쓰겠다면 그 슬라이드가 왜 있는지부터 의심한다.
- 거버닝은 한 문장, **55자 안**(기계 집행). 근거: Alley의 assertion-evidence는 문장
  헤드라인을 8–14 단어·최대 2줄로 고정하고(Garner & Alley 2013이 이 형식의 이해도
  이득을 측정), 그 분량이 한국어로 대략 25–50자다. 두 문장이 필요하면 슬라이드가 두 개다.

## 3. 전시물 규율

- **슬라이드당 전시물 하나.** 차트 둘 = 슬라이드 둘. (FigureSlide 계약이기도 하다.)
- **핵심 발견은 도판 위에 주석으로 박는다.** 청중이 찾게 하지 않는다 — FigureSlide의
  `annotations`가 그 자리다. 강조 주석은 하나만.
- **자립 슬라이드 테스트**: 발표자 없이 이 슬라이드만 봐도 요지가 전달되는가?
  안 되면 주석이나 거버닝을 보강한다. (덱은 PDF로도 돈다.)
- **논증에 필수인 근거를 노트에 두지 않는다.** 회람본에는 노트가 없다 — 근거가 노트에만
  있으면 화면만 읽는 독자에게 그 논증은 반쪽이다. 노트는 전달(순서·타이밍·화법)의 자리지
  근거의 자리가 아니다. 특히 **StatementSlide 앞에서는** 그 단언을 받치는 근거가 이전
  슬라이드들의 **캔버스 위에서** 끝났는지 확인한다. (첫 하네스 심사에서 검출: "유지할
  이유가 없습니다" 단언의 존속-비용 근거가 노트에만 있었다.)
- **추세·비교는 그래프, 정밀 수치 대조만 표.** 표가 필요한 비교가 "대안 선택"이면
  CompareSlide, "목표 대비 현황"이면 AssessmentSlide가 이미 그 문법이다.
- **사진도 전시물이다.** alt(사진이 말하는 바)·caption(무엇인지)·source(어디서 왔는지)를
  채운다 — 출처 없는 사진은 장식이고, 장식은 안티패턴이다. alt와 raw <img>의 박스 예약은
  기계 집행(img-alt·img-unsized). 분위기용 장식 사진은 싣지 않는다.
- **논문/문서의 도판을 그대로 캡처해 붙이지 않는다.** 화면 해상도에서 다시 그린다.
- 다루지 않을 전시물은 싣지 않는다. 시간이 없으면 부록으로.

## 4. 텍스트 규율

- 본문 텍스트는 슬라이드당 **~40단어(한국어 ~120자) 상한**. 넘치면 슬라이드를 쪼개거나
  대본(script.md)으로 보낸다. 폰트를 줄이는 것은 금지 — 투사 하한은 토큰의 약속이다.
- 불릿은 방향 안내지 정보 전달이 아니다. 3–5개가 정상, 5개 초과는 경고 신호.
- 전보체 허용: "본 연구는 비용을 유의미하게 절감함을 확인" ✗ → "비용 23% 절감 (p<0.01)" ✓
- 슬라이드는 발화를 대체하지 않는다. 상세 설명은 script.md의 몫.
- **상한만 규율이 아니다 — 미달도 신호다.** 그려진 내용이 캔버스 절반 위에서 끝나는
  콘텐츠 슬라이드가 덱에 **3장 이상이면 빌드가 선다**(기계 집행: canvas-under-fill —
  하네스 심사에서 두 번 연속 재발해 산문에서 게이트로 승격). 인접 슬라이드와 병합하거나
  더 찬 레이아웃(Stat·도식·표)으로 바꾼다. 한두 장의 성긴 장은 호흡이라 허용;
  Statement·Section·표지·막지의 여백은 의도된 것이라 측정 대상이 아니다.
  경계선 아래(50~66%)의 장은 여전히 심사(rubric: 마감)가 본다.
- **한 장만으로도 서는 경우: 아래로 쏠린 여백**(기계 집행: dead-bottom). 위 규칙이
  "덱에 할 말이 있는가"를 덱 단위로 묻는다면 이쪽은 "이 장이 받은 영역을 쓰는가"를
  장 단위로 묻는다. 콘텐츠 영역 아래쪽이 40% 넘게 비고 그 여백이 위쪽보다 두 배
  이상이면 선다. 고치는 법은 둘 중 하나 — 본문을 세로 중앙에 두거나(`anchor="center"`),
  더 채우거나. **`anchor`를 줬는데도 계속 서면 그 레이아웃에서 prop이 먹지 않는 것이다**
  (SplitSlide·TriptychSlide의 패널 격자가 이미 영역을 채우고 있어 그랬다). 게이트는
  선언이 아니라 결과를 재므로 prop 한 줄로 꺼지지 않는다.
- **같은 골격의 재등장을 경계한다.** 제목+거버닝+불릿 3개짜리 ContentSlide가 챕터마다
  한 번씩 나오면 그 골격이 덱의 기본값처럼 읽힌다. 내용의 핵심이 대비(잔여 2 vs 이관 5)나
  수치면 불릿이 아니라 도식·Stat이 그 슬라이드의 모양이다. (rubric: 다양성)
- **수동 개행 금지.** 어절 줄바꿈(keep-all)·제목 줄 균형(balance)·구 단위 묶음
  (phrasing.jsx: 의존명사는 앞말에, 안/못은 뒷말에, "수"는 있다/없다까지)은 매체가
  소유한다. 줄이 어색하게 꺾이면 `<br>`이 아니라 문구를 다듬거나 — 문법 단위가 찢긴
  거라면 phrasing 규칙의 빈틈으로 — 컴포넌트 결함으로 보고한다.

## 5. 강조 규율

- **슬라이드당 accent 하나.** 컴포넌트가 집행하지만(강조 예산), 작성 단계에서부터
  "이 슬라이드의 한 방"이 무엇인지 정하고 그것에만 emphasis를 준다.
- 정상 상태는 무채색이다. 색은 일탈(watch/missed)과 강조에만 쓴다.
- 모든 슬라이드에 강조가 있으면 아무 데도 강조가 없는 것이다 — 덱 전체에서 강조
  슬라이드는 소수여야 한다.

## 5½. 인용과 귀속 (원전 §5, 번안에서 떨어뜨렸던 것)

- **빌린 것마다 그 자리에서 귀속한다.** 데이터·도판·주장 모두 — 슬라이드의 `source`가
  그 자리다 (기계 집행: 데이터를 보인 위임 슬라이드는 source가 비면 실패).
- 형식은 짧게: `출처: <시스템/문서>, <YYYY-MM>`. 참고문헌 슬라이드로 미루지 않는다 —
  청중은 그 슬라이드를 보는 순간에 출처를 판단한다.
- 자기 데이터도 귀속한다("사내 운영 대시보드"도 출처다). 출처 없는 수치는 주장이 아니라
  장식이다.
- 남의 도판을 다시 그렸으면 "재구성: <원 출처>"로 표기한다. 다시 그렸다고 귀속이
  사라지지 않는다.

## 6. 덱 골격

표지 → 목차 → (간지 → 콘텐츠…)×N → 막지.

- 15장 넘는 덱은 챕터 사이에 `AgendaSlide current={n}`로 위치를 다시 알린다.
- **막지 직전은 결론 슬라이드다.** Q&A 동안 화면에 남을 것은 EndSlide의 message이므로,
  message에는 논증의 잔향(핵심 주장 or 다음 행동)을 담는다. "감사합니다"로 끝나는
  덱은 마지막 10분을 빈 화면에 버리는 것과 같다.
- 부록 챕터는 `SectionSlide index="A"` 등으로 본문과 구분한다.

## 7. 최종 체크리스트

기계가 잡는 항목(✓)과 사람이 잡는 항목(□)을 구분한다. ✓는 lds-slides-ui
저장소의 `npm run check:storybook`이 집행해 실패 시 빌드를 세운다 — **소비
레포에는 그 게이트가 없으므로 ✓도 사람이 확인한다.** □는 `qa/rubric.md`의
심사 항목이다(저장소에 있다).

```
□ 거버닝 체인만 읽어도 논증이 성립한다 (고스트 덱 테스트 → rubric: 논증)
✓ 모든 title이 명사형 종결이다                       (check:deck-content)
✓ 콘텐츠 슬라이드마다 거버닝이 있다 (한 문장·55자)     (check:deck-content)
□ 전시물은 슬라이드당 하나, 핵심 발견에 주석 (→ rubric: 적합)
✓ 데이터를 보인 슬라이드마다 source가 채워져 있다      (check:deck-content)
□ 슬라이드당 emphasis는 최대 하나로 설계했다 (컴포넌트가 집행, 의도는 rubric: 마감)
✓ 본문 텍스트 상한(140자)·불릿 상한(7)               (check:deck-content)
✓ StatementSlide는 덱에 최대 2장                    (check:deck-content)
✓ 막지 message가 감사가 아니라 잔향이다               (check:deck-content)
✓ 캔버스를 넘치는 슬라이드가 없다 (덱 전 장 순회)      (check:slide-overflow)
✓ 콘텐츠가 하단 크롬 밴드를 침범하지 않는다            (check:deck-content)
✓ FigureSlide 도판이 부여 폭의 70% 이상을 그린다        (check:figure-fill)
✓ 대표 슬라이드 렌더가 베이스라인과 일치한다           (check:visual-snapshot)
✓ (저장소 안에서 저작할 때) npm run check:storybook 통과 — 위 전부 포함
```

## 8. 열람 프로파일 (`kind="read"`)

위 규칙들은 **발표 덱**(kind 기본값 `present`)의 문법이다. 회람·열람되는
덱 — 주간보고, leave-behind — 은 `DeckViewer kind="read"`를 달고, 게이트가
프로파일을 바꾼다 (READING_DECK_PROPOSAL, 실물 파일럿: Decks/주간 업무현황
파일럿):

**read가 벗는 것 (발표 문법):**
- **거버닝 강제 해제.** 열람 관용구는 명사형 제목 + 전시물로 완결이고
  메시지 라인이 없다. 요약 문장이 필요하면 회람 메시지(메신저 본문)가
  밖에서 한다. 거버닝을 썼다면 형태 규칙(한 문장·55자)은 그대로 적용.
- **본문 상한 140→300자.** 한 페이지 한 주제(경과+수치+증거)가 이 장르의
  미덕이다.
- **canvas-under-fill·dead-bottom 해제, anchor="center" 금지.** 열람 페이지는 문서처럼
  위에서 아래로 읽힌다 — 본문은 제목에 붙고, 상단 쏠림은 결함이 아니라
  문서 흐름이다. 가운데 구도는 투사 화면의 균형 규칙이다.
- **고스트 덱 테스트는 제목 체인으로.** 명사형 제목만 이어 읽어 보고의
  목차가 서는가.

**read가 유지하는 것 (장르 무관 규율):** 명사형 종결, source, 이미지
alt·박스 예약, 불릿 상한, 강조 예산, 크롬 존 불침범(chrome-intrusion).

**빈 슬롯은 비워둔다.** 컴포넌트에 자리가 있다고 그 장르에 그 텍스트가
있는 게 아니다 — 파일럿에서 어긋난 텍스트 3건(거버닝 2회, 표지 부제)이
전부 "자리가 있어서 지어 채운" 문장이었다. **표지는 제목·소속·보고자·
주차로 완결**하고, 내용 요약 부제를 달지 않는다. 실험·제작 메타데이터는
notes와 문서의 몫이지 회람받는 사람이 보는 캔버스의 몫이 아니다.

**열람 페이지의 어휘:** 2단계 리스트는 `TopicList`(세 번째 위계는
들여쓰기가 아니라 표나 페이지 분할), 본문 곁 증거는 `ExhibitRow`(잔여
높이 주도 — 고정 px 높이 금지), 주차 계획은 `WeekSpanRows`(시간 격자 +
한 몸 스팬 바 + 계속 화살촉).
