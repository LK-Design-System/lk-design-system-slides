# 제안 — AnnotatedFigure 주석 재설계 (콜아웃 + 조용한 레일)

상태: **제안** (2026-08-17. 사용자 지적 2건 — 배치와 시각 문법 모두 — 에서 출발)

## 진단 — 현행이 실패하는 지점

1. **배치가 자기 규율을 어긴다.** content-rules §3: "핵심 발견은 도판 위에
   주석으로 박는다. 청중이 찾게 하지 않는다." 그런데 컴포넌트는 모든 주석을
   캔버스 밖 레일에 세우고, 앵커 연결의 시각 표현은 ↘ 글리프 하나다 —
   지시선도 번호도 위치 대응도 없어 독자가 지점을 찾아야 한다.
   docstring("옆에, 절대 데이터 위에 올리지 않는다")과 content-rules가
   **기록된 모순** 상태였다.
2. **시각 문법이 주석이 아니다.** border-left 2px 카드는 인용구 문법이라
   콘텐츠 블록으로 읽히고, note 랭크 semibold 제목 + note-body 본문의 2층은
   주석치고 무겁다(주석은 본문보다 조용해야 한다). 200px 협폭에서 한국어가
   서너 어절마다 꺾여 누더기가 된다. 강조는 파란 제목뿐이라 링크처럼 보인다.

## 외부 근거 (2026-08-17 실측)

- **Datawrapper**: 설명 텍스트는 관련 요소 **가까이**(시선 이동 최소화),
  직접 라벨이 범례보다 우선, 위계는 "명확히 다른 **2층까지만**", 보조
  텍스트는 "작고 얇고 회색", 데이터 위에 얹는 텍스트는 **외곽선(halo)**,
  중앙정렬 금지, 회전 금지.
- **FT/Economist·실무자 연구(arXiv 2604.07691, ChartAccent)**: 주석은 "액션이
  있는 곳"에 — 작업 기억에 들 것을 없앤다. 인접이 불가하면 **짧고, 교차하지
  않고, 데이터 마크와 구별되는 지시선**. 모든 마크에 라벨하면 역효과 —
  **가장 중요한 대상에만** 인접 라벨을 아낀다.

## 설계 — 앵커 유무가 자리를 가른다

**앵커 있는 주석 → 캔버스 위 콜아웃.**
- 도판 위, 앵커 요소의 **위 또는 아래**로 비켜 앉는다(앵커가 아래 절반이면
  위로, 아니면 아래로 — 빈 쪽으로). 옆이 아닌 이유는 실측으로 배웠다: 차트는
  좌우로 흐르므로 "점 옆"이 곧 "선 위"였고, 첫 판이 곡선을 관통해 주석을
  찍었다(사용자 지적, 2026-08-17). 위/아래로 가면 지시선도 데이터의 진행
  방향을 **가로지르게** 되어 함께 읽힌다. **짧은 지시선 + 앵커 점**이
  콜아웃과 지점을 잇는다 — 선은 데이터 마크와 구별되게 가늘고(1.5px), 강조
  콜아웃만 emphasis 색.
- 데이터 가림 방지는 "밖으로 추방"이 아니라 **halo**로 푼다(Datawrapper):
  텍스트에 표면색 외곽선을 둘러 겹침 지점에서도 읽히게 한다.
- 폭은 도판 폭 비율로 클램프(과폭 콜아웃은 도판을 가린다).
- 접근성 링크(aria-details)·앵커 미확인 노출·강조 예산 1개는 **그대로 유지**.

**밀집 도판 규칙**: 캔버스가 꽉 찬 도판(두 열 다이어그램, 밀집 표)에는
콜아웃이 앉을 여백이 없다 — 그때는 앵커를 떼고 레일을 쓰는 것이 저작
판단이다(도판 자신이 강조를 나르고 있다면 콜아웃은 중복이기도 하다).
실증: seam 다이어그램의 앵커 콜아웃이 연결선·필 위에 얹혀 첫 렌더에서
확인, 레일로 강등. 콜아웃은 **여백이 있는 차트**의 관용구다.

**앵커 없는 주석(컨텍스트) → 레일 유지, 문법 교체.**
- 특정 지점이 없는 방법론 노트("축은 각자 정직하게")는 옆이 맞다.
- border-left 카드 폐기. 리드 = **note-body 랭크 semibold strong**(한 단
  내려간다 — 주석은 본문보다 조용하다), 본문 = note-body regular neutral.
  2층 위계는 크기가 아니라 무게·색이 나른다(주석 스케일에서의 Datawrapper
  2층 규칙).
- 강조 리드만 primary-strong. 카드 장식 없음 — 간격이 구분자다.
- 협폭 누더기 해소: 최소 폭 200→240px, 리드가 한 단 작아져 줄꺾임이 준다.

## 좌표계 — 실측은 화면 px, 자리는 캔버스 px

`getBoundingClientRect()`는 **변환이 적용된 화면 px**를 준다. 그런데 좌석은
도판 안에 평범한 CSS px로 다시 쓰인다. 슬라이드 표면은 1280 논리 캔버스를
transform으로 축소하므로 두 공간이 그 배율만큼 어긋난다 — 실측 0.81배에서
439로 계산한 자리가 354에 앉아 콜아웃이 앵커에서 100px 넘게 떨어졌다.
`bodyRect.width / body.offsetWidth`로 배율을 나눠 전부 캔버스 px로 환산한다.

ResizeObserver는 이걸 못 잡는다(transform은 레이아웃 박스를 바꾸지 않는다).
컴포넌트 스토리도 못 잡는다 — 거긴 배율이 1이라 항상 맞아 보인다. 그래서
`check:figure-fill`에 **콜아웃 이탈** 규칙을 넣었다: 실제 덱의 축소된 표면
위에서 콜아웃과 앵커의 거리를 재고 48캔버스px을 넘으면 실패한다.

## 결정론 주석

콜아웃 위치는 앵커 실측(DOM rect)이다 — 이 컴포넌트는 이미 ResizeObserver로
레일 폭을 실측하고 있어 **새로운 종류의 위험이 아니다**. 모션 레포 소비 시의
주의는 기존과 동일(SKILL.md 함정 1과 같은 계열): 헤드리스 렌더는
double-rAF 정착 후 캡처하므로 실무상 안정, 프레임 함수 순수성 계약과는
무관한 정적 배치다.
